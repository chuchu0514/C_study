## Ch5. 트리 / 힙 / 이진탐색트리 / disjoint set

| # | 함정 포인트 | 핵심 |
|---|---|---|
| 1 | **n₀ = n₂ + 1** | leaf 수 = (자식2개 노드 수)+1. **n₁은 안 들어감.** 부호·방향 헷갈림 주의 |
| 2 | full vs complete | **full**: 모든 레벨 꽉 참(2^h−1개). **complete**: 마지막 레벨만 왼쪽부터, 중간에 빈 칸 없음. 둘 혼동 단골 |
| 3 | 배열 표현 인덱스 | 1-based에서 노드 i의 왼자식=**2i**, 오른자식=**2i+1**, 부모=**i/2**(정수나눗셈). 0-based면 다 +1씩 밀림 → ⚠️어느 base인지 먼저 확인 |
| 4 | traversal 순서 | inorder=LNR, preorder=NLR, postorder=LRN. **N(노드 방문)이 어디 끼냐**로 외우기 |
| 5 | threaded BT | thread는 **NULL 링크를 inorder 선행자/후행자로 재활용**. right thread→inorder **successor**, left thread→inorder **predecessor** |
| 6 | heap 종류 함정 | ⚠️ **PPT가 min-heap 예제면 시험은 max-heap**(교수님 패턴). 문제에 "max"인지 "min"인지 먼저 동그라미 |
| 7 | heap delete | 루트 제거 → **마지막 노드를 루트로** 올리고 → 아래로 heapify(자식 중 큰/작은 것과 교환) |
| 8 | makeMaxHeap | 배열 → 힙: **마지막 비단말 노드부터(n/2) 거꾸로 위로** heapify. 위에서부터 X |
| 9 | BST delete | 자식 2개인 노드 삭제 시: **왼쪽 서브트리의 최대(=오른쪽 끝)** 또는 **오른쪽 서브트리의 최소(=왼쪽 끝)**로 대체 |
| 10 | union 방식 | **weightedUnion**=노드 적은 트리를 많은 트리 밑에. simpleUnion=무조건 한쪽 밑. → weighted가 트리 높이 억제 |
| 11 | collapsing find | find 하면서 **거친 노드들을 전부 루트 직속 자식으로** 경로 압축. (단답 빈칸 후보) |
| 12 | selection tree | winner tree: 부모=자식 중 **승자(작은 값)**. 다음 꺼낼 때 진 경로만 갱신 |

## Ch6. 그래프

| # | 함정 포인트 | 핵심 |
|---|---|---|
| 1 | 인접행렬 vs 리스트 | 행렬: 공간 **O(V²)**, 간선존재 확인 O(1). 리스트: 공간 **O(V+E)**, 희소그래프 유리 |
| 2 | DFS/BFS 순서 | ⚠️ **인접 정점을 번호 작은 순? 큰 순?** 으로 방문하는지 문제 조건 확인 → 순서 통째로 갈림 |
| 3 | DFS 자료구조 | **stack(재귀)**, BFS = **queue** |
| 4 | spanning tree 간선 수 | 정점 V개 → 신장트리 간선 항상 **V−1개** |
| 5 | **Kruskal vs Prim** 🔥 | Kruskal=**간선 정렬, 작은 것부터, 사이클 안 생기면 채택(union-find)**. Prim=**한 정점에서 시작, 트리에 붙는 최소 간선 확장**. → 둘 구분 + 결과 트리 단골 |
| 6 | Kruskal 사이클 판정 | 두 정점이 **같은 집합(find 결과 같음)**이면 추가 시 사이클 → 버림 |
| 7 | Dijkstra | 빈칸 단골. **방문 안 한 정점 중 거리 최소** 선택 → 인접 정점 거리 갱신(relax). 음수 간선 X |

## Ch7. 정렬

| # | 함정 포인트 | 핵심 |
|---|---|---|
| 1 | **stability(안정성)** 🔥 | 안정: insertion, merge, (LSD) radix. **불안정: quick, heap, selection**. → "다음 중 stable한 것?" 단골 |
| 2 | 시간복잡도 표 | quick 평균 O(n log n)/**최악 O(n²)**, merge 항상 O(n log n), heap O(n log n), insertion 최악 O(n²)/거의정렬시 O(n) |
| 3 | merge 공간 | merge sort는 **추가 배열 O(n) 필요**(in-place 아님). quick/heap은 in-place |
| 4 | **radix sort** 🔥 | LSD: **최하위 자리부터** 버킷 분배. **각 pass 결과**를 단답으로 자주 물음 → pass별 트레이싱 연습 |
| 5 | radix 안정성 의존 | radix가 작동하려면 각 자리 정렬이 **stable**해야 함 (그래서 보통 counting 사용) |
| 6 | quick pivot | pivot 기준 분할. 이미 정렬된 입력 + 첫원소 pivot → **최악 O(n²)** |
| 7 | 비교정렬 하한 | 비교 기반 정렬의 하한 = **Ω(n log n)** (결정트리 leaf ≥ n! 논증) |
| 8 | heap sort 방향 | max-heap → **오름차순** 결과(루트 빼서 뒤로). ⚠️ 실습은 min-heap으로 내림차순 냈었음 — 방향 헷갈림 |

## Ch8. 해싱

| # | 함정 포인트 | 핵심 |
|---|---|---|
| 1 | **loading factor** | **α = n/(s·b)**. 분모 **s·b**(전체 slot). b만 쓰면 틀림 |
| 2 | collision vs overflow | 다른 개념. **단 s=1이면 동시 발생** |
| 3 | division D | **큰 소수** 권장. 작은 소인수(2,3,5,7) 있으면 편향. p14 표(%6 편향 vs %7 균등) |
| 4 | folding 2종 | shift=다 더함(699). boundary=**번갈아 reverse 후** 더함(897). 값 다름 |
| 5 | mid-square | r비트 추출 → 테이블 크기 **2^r** |
| 6 | linear probing 단점 | **clustering(군집화)** → search time 증가 (빈칸 단골) |
| 7 | **quadratic 조건** | **b=4j+3 형태 소수**면 모든 bucket 조사 보장. 숫자조건 "4j+3" |
| 8 | chaining 평균 | **1 + α/2**. 최악 O(n). ⚠️ 여기 α=**ids/head nodes**(=ids/b), probing α(n/sb)와 정의 다름 |
| 9 | **dynamic hashing 비트순** | **LSB→MSB** 순으로 분기. 반대로 읽으면 페이지 다 틀림 |
| 10 | directory depth | h(k,d) → directory 크기 **2^d** |
| 11 | overflow splitting | overflow 난 **그 페이지만 쪼갬**, 나머지는 directory만 2배 + 기존 페이지 **공유** |
| 12 | directory 도입 이유 | trie 직접의 ①비트수 의존 ②skew 문제 해결 |
